Jexter is a thin front over the jexter Java library. The same normalization you see here is one static call — embed it in your own JVM code, no server, no HTTP. Needs the jexter jar on the classpath (JDK 21+).

The one call


    

    
It returns the OCDDocument (page count, etc.) and writes the
       normalized PDF to out — always with a real selectable text layer.

 Hot folder (daemon)

    
Watch a folder and normalize every PDF that lands — headless, no window. Outputs are written
       atomically (temp + rename); --recursive mirrors the sub-tree, --threads runs in parallel:

    

      
      

    



    
The normalization is fixed and baked into
      Jexter.normalize — text segmentation on, headers/footers off, navigation recovered
      only when absent, annotations kept, always a selectable text layer. Nothing to pass, nothing to configure.
